# 주거금융 지원가능성 판정 Agent

전세 대출·보증을 신청하기 전에 **"내 조건으로 될 것 같은지"를 공식 문서 근거와 함께 알려 주는 시스템**입니다.

사용자가 채팅으로 자기 상황을 말하면, 문장에서 나이·소득·무주택 여부 같은 조건을 뽑아내고 주택도시기금·HUG의 공식 자격 요건과 하나씩 대조합니다.

> **승인 여부를 판단하는 시스템이 아닙니다.** 실제 심사는 기관이 합니다. 이것은 신청 전에 가능성을 가늠하는 도구이며, 결과에 `승인`이나 `자격 있음` 같은 확정 표현을 쓰지 않습니다.

## 이 프로젝트가 증명하려는 것

금융에서 가장 위험한 것은 **틀린 답을 자신 있게 하는 것**입니다. "신청 가능합니다"라고 했는데 거절되면 사용자는 시간과 비용을 잃습니다. 그래서 뼈대를 둘로 잡았습니다.

**1. 판정은 규칙이 하고, LLM은 설명만 씁니다.**

조건 비교를 LLM에 맡기면 왜 그 결과가 나왔는지 추적할 수 없고, 같은 입력에 다른 답이 나옵니다. 판정 엔진은 LLM이 닿지 않는 자리에 둡니다. LLM은 이미 정해진 결과를 문장으로 풀어 쓸 뿐이고, 그 단계에서 판정을 바꿀 수 없습니다.

**2. 모든 조건에 출처가 붙습니다. 출처를 못 대는 조건은 판정에 쓰지 않습니다.**

규칙마다 어느 문서 어느 문장에서 나왔는지를 함께 저장합니다. LLM이 문서에서 뽑은 규칙은 후보일 뿐이고, 사람이 원문과 대조해 확인한 것만 판정에 들어갑니다.

이 방식이 필요하다는 것은 첫 수집에서 바로 드러났습니다. 웹 검색 요약과 공식 페이지의 값이 두 건 달랐고, 심지어 **공식 출처 두 곳의 보증료율이 서로 달랐습니다.**

| 항목 | 검색 요약 | 공식 페이지 |
|---|---|---|
| 버팀목 순자산 기준 | 3.37억원 | **3.45억원** |
| HUG 보증료율 | 0.115%~0.154% | **0.097%~0.211%** |

## 판정 결과

네 가지만 씁니다.

| 결과 | 뜻 |
|---|---|
| `사전 조건 부합` | 확인 가능한 조건을 전부 통과 |
| `추가 확인 필요` | 필수 조건은 통과했으나 기관 심사가 남음 |
| `조건 불충족` | 확인된 필수 조건 중 불충족이 있음 |
| `정보 부족` | 판정에 필요한 값이 아직 없음 |

## 규칙을 데이터로 두는 이유

자격 조건을 파이썬 코드로 짜면 가장 빠르지만, **조건마다 출처를 붙일 자리가 없고 사람이 검수하려면 코드를 읽어야 합니다.** 그래서 규칙을 데이터로 두고 평가기 하나가 읽는 구조로 만들었습니다.

```yaml
- rule_id: B-02
  field: age
  operator: lte
  value: 34
  unit: 세
  type: HARD
  citation: "만 19세 이상 ∼ 만 34세 이하의 세대주(예비 세대주 포함)"
  human_reviewed: false
  failure_message: 만 34세를 넘으면 신청 대상이 아님
```

`human_reviewed`가 `false`인 규칙은 판정에 쓰지 않습니다. `이하`와 `미만`, `이전`과 `이내`, 수도권과 비수도권처럼 한 글자 차이로 결과가 갈리는 조건이 많습니다.

조건부 기준값은 특례 규칙이 일반 규칙을 덮는 방식으로 다룹니다. 예를 들어 전용면적은 85㎡가 일반이고, 만 25세 미만 단독세대주면 60㎡ 규칙이 일반 규칙을 대신합니다.

## 대상 상품

| 상품 | 기관 | 상태 |
|---|---|---|
| 청년전용 버팀목전세자금 | 주택도시기금 | 규칙 16개 확보, 검수 대기 |
| 전세보증금반환보증 | HUG | 일부 규칙 미확보 |
